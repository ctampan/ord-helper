# ORD 2.323 data

Source: [Sions post 13347](https://sions.kr/bbs/board.php?bo_table=mk_helper&wr_id=13347), inspected on 2026-10-10. The HTML-encoded JSON is embedded in `#wr_content_json`; the helper button changes presentation without loading another dataset. Source portraits use `https://sions.kr/data/file/mk_helper_thumb/`.

The 303 source rows become 278 units/items and 17 rarities. Twenty-five reference/separator rows become subgroup labels or shared notes. All 278 retained source recipes were compared with the converted graph. Common units intentionally have no Wisp recipes, so Wisp substitution remains optional.

Names keep the existing English character/form names and stable IDs. HP/Mana activation requirements are restored from map evidence as separate filter categories, rather than name suffixes. Upgrade conditions remain attached to the relevant effects. The original Sions conversion supplied translated notes for 251 entries; these are now split into capabilities, ability details, and important notes as described below. Shared `Group reference:` summaries are removed from unit notes and retained only in the audit. No old gameplay notes were copied without checking the current source.

Where the source title and description disagree (including Legendary Kuma, Kalgara, Hibari, Zoro, Hidden Sunny, Transcendence Doflamingo, Franky, and Koby), the notes distinguish both claims. Single-target values whose precise meaning is not specified are retained without inventing a percentage or duration. Gold, wood, tokens, zombies, and extra random-unit requirements remain informational when they cannot be represented by the existing unit recipe schema.

## Capability filters and values

The supplied ORDSearch helper DOM (`ref/ref.html`) supplies the 25 categories and fallback membership. Verified object data from the supplied 2.323 Warcraft map can correct or supplement numeric effects; ambiguous map mechanics keep the existing ORDSearch/Sions data. Its 304 non-Common unit/material rows are matched by rarity and Korean character/form names, with explicit aliases for differently named forms and materials. Of the 268 non-Common app entries, 267 match; the generic Sions Seraphim crafting material has no equivalent ORDSearch row. Common units have no skill-filter rows in this snapshot. All 278 entries are accounted for in `capability-audit-2.323.json`, including original translated notes, both source IDs, subgroup, source flags, and value discrepancies. Recipes, portraits, IDs, subgroup membership/order, and rarity layout are unchanged.

The primary snapshot contains 157 numeric effect records. Numeric reductions are kept separate and identical exported records are deduplicated; no totals are calculated. The reference's public `js/mix-helper.js?id=88dde7e0eba782033d8e&v=20260725-2` was read to verify that shield type 3 denotes Armor Break (its raw `value` is ignored by the reference's calculation), rather than ordinary armor reduction. Shield types 1/2/4 represent aura/single-target/skill reductions. Type 6 is the story/lane reduction in the two matching Sions entries. The same script explicitly formats movement slow with `%` and treats slow type 5 as a single-target addition. Other unnamed slow mechanisms are displayed as separate additional effects without inventing a target or stacking rule.

Sions remains the source of subgroup labels/order, supplementary abilities, duration, and conditions. Values are shown on compact capability tags, separate from recipe content. Source labels are hidden in the UI; optional metadata and the audit preserve provenance. Clear map evidence takes precedence; otherwise ORDSearch wins numeric disagreements and alternative values/context remain readable. The preserved original notes are also audited for numeric information loss. Missing numeric data is never replaced with zero or an invented unit.

The `singlelost` filter exists in the primary DOM but has no per-unit flags; `ignore` flags are all N. Sions explicitly supplies armor-ignoring damage for Eternal Mihawk and the conditional Atlas choice of Vegapunk. Koby's conflicting title/description is retained without assigning armor-ignoring damage. Missing-HP damage with unspecified targeting is not assumed to be single-target. Unqualified stun values are assigned to Area stun only when supported by the primary area-stun flag. Upgrade/form/skill-choice capabilities retain their conditions and do not participate in base-ability filtering; ordinary mana/HP skills do. A trailing upgrade marker does not gate earlier base abilities.

`Unit.capabilities` contains `{ category, source?, detail?, condition? }` records; optional source values are `ordsearch`, `sions`, and `warcraft-map`; `abilityDetails` stores remaining descriptive ability information, and `note` retains commands, restrictions, crafting costs, stacking warnings, and source disagreements. These optional fields round-trip through Custom import/export. Old JSON without them remains valid and is not parsed into categories at runtime.

The full-width panel above the unchanged seven-column dashboard is shown by default. Config toggles visibility of the entire component; when hidden, no filter panel is mounted. The panel header independently collapses choices while the panel remains visible. Its expansion state persists separately in `ord_capability_filter_choices_expanded` (default true), including refresh and hiding/showing the panel. Hiding or collapsing keeps filtering active, and saved selections are preserved. The visible header shows selection/result counts and Clear. All/Any selection, base-ability counts, and empty results are supported. Preferences use `ord_capability_filters`; visibility persists separately using the legacy storage key in `ord_capability_filters_expanded`. Only dashboard visibility changes: inventory, bans, crafting, shortcuts, and recipe navigation use the complete graph. Hidden groups remain mounted so their collapse state survives filtering. Abilities render in a compact sibling panel to the right, then left, when at least 220 px is available (maximum width 280 px). Otherwise a collapsed Abilities disclosure follows the recipe. Recipe and ability panels scroll independently and remain inside a 10 px viewport margin. Longer descriptions are always expanded inside tooltip ability panels. Modal abilities follow the unit's notes/commands and precede the recipe, with longer descriptions in a disclosure. Display text normalizes legacy Unicode minus to ASCII `-`.

Raw reference inputs are not included in the repository; `ref/` is reserved for local, Git-ignored inputs. Rebuild capability data with `python scripts/build-capabilities.py` after saving the ORDSearch DOM to `ref/ref.html` and the decoded Sions `#wr_content_json` to `ref/sions.json` (Python with `beautifulsoup4` required only for this offline script). Every Sions-to-app match is checked against its recipe. Also extract `ref/map-2.323.json` first as described in `capability-map-2.323.md`; regeneration requires this snapshot so verified map corrections cannot silently disappear. The audit preserves pre-migration notes for deterministic repeated runs. Source scripts are never executed by this conversion, and no external requests are made by the app.

Currently only 2.323 is shipped. All `public/data/*.json` files are discovered automatically at build time and included in the application bundle. To add a future version, add `public/data/<version>.json` with matching `version` metadata, then build and deploy as usual. No separate version manifest or application code changes are required. Versions are sorted numerically, newest first; new visitors start with the latest version, while returning users keep their selected version if it is still available. Valid stored Custom data remains an additional option.

Startup and dataset switching do not fetch a version manifest or game-data JSON. Public JSON files remain available for direct downloads. Users with retired selected versions migrate during initialization. Selecting a version updates the dashboard in one render, without a reset confirmation or an intermediate loading/error screen. Inventory and bans for IDs available in the destination are retained; unavailable IDs are removed. Shortcut preferences remain available. The runtime uses the existing GitHub Pages base path.

A temporary 2.324 file was also tested in a production build: automatic discovery, latest defaults for new visitors, preserved selections for returning users, migration, dropdown switching, inventory/bans, and reload all passed with JSON requests blocked and no dashboard unmount or confirmation dialog. The temporary dataset was removed afterward.
